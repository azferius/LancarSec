# balooProxy / LancarSec - Architecture Reference

Derived from a full read of all 25 `.go` files at commit `4d4f128`. This is *descriptive*:
it documents how the code works today, before any LancarSec change. Fixes live in
[AUDIT.md](AUDIT.md); this file is the map you need to make sense of them.

---

## Entry point, config load, and HTTP/TLS serve path (main.go, core/config, core/proxy, core/server/serve.go + monitor.go bootstrap)

balooProxy is a single-binary reverse proxy whose entire startup is a straight-line sequence in `main.go`: install a panic handler, discard the stdlib logger, run `config.Load()` synchronously (which parses `config.json`, validates secrets, fetches TLS-fingerprint tables over the network from GitHub, compiles gofilter firewall rules per domain, loads X.509 keypairs, and populates the global `domains.DomainsMap` / `domains.DomainsData`), then spawn `server.Monitor()` (terminal UI + four background goroutines) and busy-wait on the `proxy.Initialised` boolean before spawning `server.Serve()`. All runtime state lives in package-level mutable globals across `core/proxy`, `core/domains`, and `core/firewall`, guarded by one process-wide `firewall.Mutex` (`*sync.RWMutex`). `Serve()` branches once, at startup, on `domains.Config.Proxy.Cloudflare`: true means a single plaintext `:80` listener; false means `:80` (301-redirect handler) plus `:443` with `GetConfigForClient: firewall.Fingerprint` and `GetCertificate: domains.GetCertificate` for SNI cert resolution. There is no graceful shutdown of any kind — no `signal.Notify`, no `http.Server.Shutdown`, no context; `main()` blocks forever on a bare `select{}` and every listener error path calls `panic()`. Config can be re-read at runtime only through the interactive `reload` command, which runs `server.ReloadConfig()` (a near-duplicate of `config.Load()` living in `core/server/monitor.go` to dodge an import cycle) and cannot change the already-bound listeners.

### Control and data flow

## 1. Package init (before main)

`core/firewall/filter.go:5` `init()` registers all 26 gofilter DSL field names (`ip.src`, `http.path`, `proxy.stage`, …). This must run before any `gofilter.NewFilter` call in `config.Load`; Go's package-init ordering guarantees it because `config` imports `firewall`.

Package-level var initialisers fire at the same time: `core/proxy/proxy.go:35-43` sets timeout defaults (Idle 5, Read 5, Write 7, ReadHeader 5) and their `time.Duration` forms; `proxy.go:45` sets `RatelimitWindow = 120`; `proxy.go:59` sets `Initialised = false`. `core/firewall/general.go:10-36` allocates `Mutex` and all six ratelimit maps plus `Connections`. `core/firewall/fingerprint.go:12-49` hardcodes three fingerprint tables. `core/utils/text.go:18` sets `ColorsString = "0;31"`.

## 2. main() — `main.go:17-51`

1. `main.go:19` — copies the linker-stamped build fingerprint into `proxy.Fingerprint`.
2. `main.go:21-25` — opens `crash.log` (`O_WRONLY|O_CREATE|O_APPEND`, 0644) into a local `logFile` that is **never used** (only `defer logFile.Close()`), because `main.go:32` sets `log.SetOutput(io.Discard)`.
3. `main.go:27` — `pnc.InitHndl()` opens `crash.log` a **second** time into `pnc.logFile` (`core/pnc/panicHandler.go:16`). That is the handle actually written to.
4. `main.go:29` — `defer pnc.PanicHndl()`.
5. `main.go:36` — `config.Load()`, fully synchronous (see §3).
6. `main.go:42` — `go server.Monitor()`.
7. `main.go:43-45` — busy-wait: `for !proxy.Initialised { time.Sleep(500ms) }`. Unsynchronised read of a plain `bool` written from another goroutine.
8. `main.go:47` — `go server.Serve()`.
9. `main.go:50` — `select {}` blocks forever.

## 3. config.Load() — `core/config/init.go:25-235`

- `init.go:27-34` — `os.Open("config.json")`. On `os.IsNotExist` it calls `Generate()` (interactive, see §4) and **falls through with `file == nil`**; any other error panics.
- `init.go:36` — `json.NewDecoder(file).Decode(&domains.Config)`; the returned error is discarded. In the generated-config path this decode fails harmlessly (`*os.File` nil-receiver returns `ErrInvalid`) and `domains.Config` keeps the value `Generate()` stored at `generate.go:46`.
- `init.go:38` — mirrors `Config.Proxy.Cloudflare` into `proxy.Cloudflare`.
- `init.go:40-63` — pulls `cookie` / `javascript` / `captcha` secrets out of `Config.Proxy.Secrets` plus `AdminSecret` and `APISecret`; each is checked with `strings.Contains(..., "CHANGE_ME")` and panics if it matches.
- `init.go:67-85` — per-field timeout override: only non-zero config values replace the `core/proxy` defaults, writing both the int and the `time.Duration`.
- `init.go:88-90` — `utils.SetColor(Config.Proxy.Colors)` if non-empty.
- `init.go:92-95` — `RatelimitWindow` clamped up to a minimum of 10, then copied into `proxy.RatelimitWindow`.
- `init.go:97-100` — the four ratelimit thresholds are read from the `Ratelimits` map into `proxy.IPRatelimit`, `FPRatelimit`, `FailChallengeRatelimit`, `FailRequestRatelimit`.
- `init.go:102-106` — three blocking `http.Get` calls to `raw.githubusercontent.com/41Baloo/balooProxy/main/global/fingerprints/*.json` via `GetFingerprints` (`generate.go:102-119`), overwriting the hardcoded `firewall.KnownFingerprints` / `BotFingerprints` / `ForbiddenFingerprints`. **The returned errors are ignored at the call sites**, so a network failure silently leaves the compiled-in defaults.
- `init.go:108-193` — per-domain loop:
  - `init.go:109` appends the name to `domains.Domains`.
  - `init.go:113-124` compiles every `firewallRules[].expression` with `gofilter.NewFilter`; a compile error panics with the rule index.
  - `init.go:126-130` builds `httputil.NewSingleHostReverseProxy(&url.URL{Scheme: domain.Scheme, Host: domain.Backend})` and assigns `dProxy.Transport = &server.RoundTripper{}` (this is why `config` imports `server`, which is why `ReloadConfig` cannot live in `config`).
  - `init.go:132-139` loads the X.509 keypair with `tls.LoadX509KeyPair(domain.Certificate, domain.Key)` **only when `!proxy.Cloudflare`**; failure panics. In Cloudflare mode the cert stays a zero `tls.Certificate`.
  - `init.go:141-163` stores the immutable `domains.DomainSettings` (rules, reverse proxy, cert, webhook, all six stage thresholds) into the `sync.Map` `domains.DomainsMap`.
  - `init.go:165-192` takes `firewall.Mutex.Lock()`, defaults `Stage2Difficulty` to 5 if 0, and writes the mutable `domains.DomainData` (Stage 1, all counters zeroed) into the plain map `domains.DomainsData`.
- `init.go:195-222` — registers a synthetic `"debug"` entry in both `DomainsMap` and `DomainsData`, with `Stage: 0`.
- `init.go:224-227` — `VersionCheck()` (`init.go:237-265`): `http.Get` on `.../global/proxy/version.json`, unmarshals `GLOBAL_PROXY_VERSIONS`, and if `StableVersion > proxy.ProxyVersion` (1.5) prints a notice and **sleeps 10 seconds**. Any network/JSON error returns an error which the caller turns into a `panic` — i.e. GitHub being unreachable is a hard startup failure.
- `init.go:229-234` — if `len(domains.Domains) == 0` it calls `AddDomain()` then **recurses into `Load()`**; otherwise `proxy.WatchedDomain = domains.Domains[0]`.

## 4. Interactive generation — `core/config/generate.go`

`Generate()` (`generate.go:14-60`) builds a `domains.Configuration` from `utils.AskBool/AskInt` prompts, mints `AdminSecret` (25 chars) and `APISecret` (30 chars) plus the three challenge secrets (20 chars each) via `utils.RandomString`, assigns `domains.Config = &gConfig` (`generate.go:46`), marshals to `config.json` with `ioutil.WriteFile(..., 0644)`, then calls `AddDomain()`. `AddDomain()` (`generate.go:62-100`) prompts for name/backend/scheme/cert/key/webhook and the six stage thresholds, appends to `domains.Config.Domains`, and rewrites `config.json`. A second, drifted copy of this dialogue exists at `core/utils/domain.go:11-48` (it omits `Stage2Difficulty`) and is what the TUI `add` command calls.

## 5. server.Monitor() — `core/server/monitor.go:34-99`

Runs on its own goroutine. Clears the screen, seeds the cached clock globals (`proxy.LastSecondTime`, `LastSecondTimeFormated`, `LastSecondTimestamp`, `Last10SecondTimestamp` via `utils.TrimTime`, `CurrHour`, `CurrHourStr`) at `monitor.go:43-48`, then spawns four goroutines:

- `commands()` (`monitor.go:286`) — stdin scanner for `stage` / `domain` / `add` / `clrlogs` / `reload` / `help`.
- `clearProxyCache()` (`monitor.go:533`) — every 2 min, under `firewall.Mutex.Lock()`, drains `firewall.CacheIps` and `CacheImgs` but only when `(cpu < 15 && mem > 25) || mem > 95`.
- `generateOTPSecrets()` (`monitor.go:639`) — every 1 hour, recomputes `proxy.CookieOTP` / `JSOTP` / `CaptchaOTP` as `utils.EncryptSha(secret, time.Now().Format("2006-01-02"))`. Note the loop period is hourly but the bucket key is the **date**, so the value only actually changes at midnight.
- `evaluateRatelimit()` (`monitor.go:576`) — every 5 s: pre-creates 12 sliding-window buckets (`for i := Last10SecondTimestamp; i < Last10SecondTimestamp+120; i += 10`), then rebuilds the flat `firewall.AccessIps`, `AccessIpsCookie`, `UnkFps` maps by summing the `Window*` maps and deleting buckets older than `proxy.RatelimitWindow`. **`monitor.go:631` sets `proxy.Initialised = true`** — this is the sole writer, and it is what releases main's busy-wait.

The Monitor loop body then runs once per second: measures terminal size via `term.GetSize`, recomputes `proxy.MaxLogLength = height - 15`, takes `firewall.Mutex.Lock()` and calls `checkAttack` for every entry in `domains.DomainsData` (stage escalation/de-escalation and webhook dispatch, `monitor.go:102-209`), then `printStats()` (`monitor.go:211-284`) which also re-seeds the clock globals and reads CPU via `gopsutil` and RAM via `runtime.ReadMemStats`.

## 6. server.Serve() — `core/server/serve.go:31-116`

Branches **once** on `domains.Config.Proxy.Cloudflare` (`serve.go:35`), reading the config struct directly rather than `proxy.Cloudflare`.

**Cloudflare branch (`serve.go:37-52`)** — one `http.Server` on `:80`:
- Timeouts from `proxy.*Duration`, `MaxHeaderBytes: 1 << 20`.
- `http2.ConfigureServer(service, &http2.Server{})` with a zero-value `http2.Server` (no `MaxConcurrentStreams`/`MaxReadFrameSize` limits set).
- `SetKeepAlivesEnabled(true)`, `Handler = http.HandlerFunc(Middleware)`.
- No `ConnState` hook, no TLS.
- `ListenAndServe()`; any error → `panic(err)`.

**Direct branch (`serve.go:55-114`)** — two servers:
- `service` on `:80` with `ConnState: firewall.OnStateChange`.
- `serviceH` on `:443` with `ConnState: firewall.OnStateChange` and `TLSConfig{ GetConfigForClient: firewall.Fingerprint, GetCertificate: domains.GetCertificate, Renegotiation: tls.RenegotiateOnceAsClient }`. No `MinVersion`, no `CipherSuites`, no `NextProtos`.
- Both get `http2.ConfigureServer`.
- The `:80` handler (`serve.go:82-100`) looks up `domains.DomainsData[r.Host]` under `firewall.Mutex.RLock()`, 200s a plaintext "does not exist" message for unknown hosts, otherwise takes a full write lock to do a read-modify-write `TotalRequests++` on the map, then issues a 301 to `"https://"+r.Host+r.URL.Path+r.URL.RawQuery`.
- `serviceH.ListenAndServeTLS("", "")` runs in a goroutine with its own `defer pnc.PanicHndl()`; `service.ListenAndServe()` runs on the calling goroutine. Both `panic(err)` on any error.

## 7. TLS handshake path (direct mode only)

For each incoming TLS connection Go calls, in order:
1. `firewall.Fingerprint` (`core/firewall/fingerprint.go:52-87`) as `GetConfigForClient`. It closes the connection if `len(CipherSuites) == 0`; otherwise it concatenates `CipherSuites[1:]`, `SupportedCurves[1:]` and `SupportedPoints[:1]` into a `0x…,`-delimited string and stores it under `Connections[conn.RemoteAddr().String()]` behind `Mutex.Lock()`. It always returns `(nil, nil)` — it is used purely as a side-effect hook, never to vary the TLS config.
2. `domains.GetCertificate` (`core/domains/util.go:16-24`) as `GetCertificate`: `DomainsMap.Load(clientHello.ServerName)`, returning `&settings.DomainCertificates` on hit and `(nil, nil)` on miss.

`firewall.OnStateChange` (`core/firewall/general.go:38-50`) fires on `http.ConnState` transitions and, on `StateHijacked`/`StateClosed`, deletes the `Connections[remoteAddr]` entry under `Mutex.Lock()`.

## 8. Upstream / backend path

Each domain's `httputil.ReverseProxy` uses `&server.RoundTripper{}` (`serve.go:118-196`). `RoundTrip` borrows a `*bytes.Buffer` from `bufferPool` (`serve.go:24-28`), resolves a transport via `getTripperForDomain(req.Host)` (`serve.go:212-219`), and on dial error or a 5xx response synthesises an HTML error page returned with **`StatusCode: http.StatusOK`** (`serve.go:147`, `serve.go:190`). `getTripperForDomain` stores the *same* `defaultTransport` pointer (`serve.go:198-210`: `InsecureSkipVerify: true`, `MaxIdleConns: 10`, `MaxConnsPerHost: 10`) for every domain key, so the `transportMap` provides no per-domain differentiation.

## 9. Runtime reload — `server.ReloadConfig()` (`monitor.go:401-531`)

Triggered only by the TUI `reload` and `add` commands. Resets `domains.Domains`, re-opens and re-decodes `config.json` (panicking on open failure), re-applies `Cloudflare`, the three challenge secrets, the timeouts, colours and the four ratelimit thresholds, then repeats the whole per-domain build (rule compile, reverse proxy, cert load, `DomainsMap.Store`, `DomainsData` write). It ends with `proxy.WatchedDomain = domains.Domains[0]`.

Differences from `config.Load`: it does **not** re-read `AdminSecret`/`APISecret`, does **not** do the `CHANGE_ME` checks, does **not** clamp or apply `RatelimitWindow`, does **not** re-fetch fingerprints, does **not** run `VersionCheck`, does **not** default `Stage2Difficulty` (so reloaded domains get `Stage2Difficulty: 0`), and does **not** re-register the `"debug"` entry.

## 10. Shutdown

There is none. `grep -rn "ListenAndServe|Shutdown|os.Signal|signal\.|os.Exit"` over the tree matches only the three `ListenAndServe*` calls in `serve.go` (lines 50, 107, 112). No `os/signal` import exists anywhere. `main()` ends in `select {}` (`main.go:50`), the servers are never stored in a reachable variable, and the only exit paths are an unrecovered panic or SIGKILL. `pnc.PanicHndl` (`core/pnc/panicHandler.go:23-32`) recovers, allocates a 4 MB stack buffer, appends the trace to `crash.log`, and immediately re-panics — so a panic in any handler still tears the process down.

### Gotchas

- `server.Serve()` reads `domains.Config.Proxy.Cloudflare` exactly once at `core/server/serve.go:35`. The listener topology is frozen at that moment: flipping `cloudflare` in config.json and running the TUI `reload` updates `proxy.Cloudflare` (`core/server/monitor.go:412`) and the middleware's behaviour but never rebinds sockets, so you end up with a `:80`-only listener behaving as if it terminated TLS, or a `:443` listener with certs the middleware no longer expects.
- `config.Load()` at `core/config/init.go:224-227` panics if `VersionCheck()` fails, and `VersionCheck` (`init.go:237-253`) fails on any `http.Get` / read / JSON error against `raw.githubusercontent.com`. The proxy therefore refuses to boot with no outbound internet or if GitHub is down. It also unconditionally `time.Sleep(10 * time.Second)` (`init.go:260`) when a newer version is advertised.
- The three `GetFingerprints` calls at `core/config/init.go:104-106` return an `error` that is discarded at the call site. A failed or truncated fetch silently leaves the small hardcoded tables from `core/firewall/fingerprint.go:12-49` in place, so fingerprint classification degrades with zero log output.
- `core/config/init.go:27-36`: when `config.json` is missing, `Generate()` runs and then execution falls through to `json.NewDecoder(file).Decode(...)` with `file` still `nil`. It happens to work only because `(*os.File).Read` on a nil receiver returns `ErrInvalid` and the `Decode` error is discarded — `domains.Config` survives because `Generate()` assigned it at `core/config/generate.go:46`.
- `config.Load()` is recursive: `core/config/init.go:229-231` calls `AddDomain()` then `Load()` again when zero domains are configured. The second pass re-runs the GitHub fingerprint fetch and `VersionCheck` (including its 10-second sleep) from scratch.
- `proxy.Initialised` (`core/proxy/proxy.go:59`) is a plain `bool` written from the `evaluateRatelimit` goroutine at `core/server/monitor.go:631` and polled from `main` at `main.go:43-45` with no atomic or mutex — an unsynchronised cross-goroutine access. It is also the *only* goroutine in `Monitor` without a `defer pnc.PanicHndl()` (`monitor.go:576-578`), so a panic there kills the process without a crash.log entry.
- `crash.log` is opened twice: once in `main.go:21` into a variable that is only ever `Close()`d, and once in `pnc.InitHndl()` (`core/pnc/panicHandler.go:16`) into the handle actually written. `log.SetOutput(io.Discard)` at `main.go:32` means the stdlib logger writes nowhere at all.
- `(*RoundTripper).RoundTrip` returns `StatusCode: http.StatusOK` for both backend dial failures (`core/server/serve.go:147`) and upstream 5xx responses (`core/server/serve.go:190`). Every backend outage is reported to clients, monitoring, and CDNs as a 200.
- `getTripperForDomain` (`core/server/serve.go:212-219`) stores the identical `defaultTransport` pointer under every domain key, so `transportMap` is a no-op indirection. That shared transport hardcodes `InsecureSkipVerify: true` (`serve.go:206`) — backend TLS is never verified — and caps `MaxIdleConns`/`MaxConnsPerHost` at 10 for the entire proxy.
- The `:80` redirect handler builds its Location as `"https://"+r.Host+r.URL.Path+r.URL.RawQuery` (`core/server/serve.go:99`) with no `?` separator, so `/a?b=c` redirects to `https://host/ab=c`.
- That same handler does a read-modify-write of `domains.DomainsData[r.Host]` under a full `firewall.Mutex.Lock()` on every redirect (`core/server/serve.go:93-97`), and unknown hosts get a 200 with a plaintext body rather than a 404 (`serve.go:87-91`).
- `domains.GetCertificate` returns `(nil, nil)` for an unknown SNI (`core/domains/util.go:23`) rather than an error. Because `TLSConfig.Certificates` is never populated in `core/server/serve.go:71-75`, there is no fallback certificate. The synthetic `"debug"` domain registered at `core/config/init.go:195-197` has a zero-value `DomainCertificates`, so SNI `debug` resolves to an empty certificate.
- `firewall.Fingerprint` (`core/firewall/fingerprint.go:66,71`) deliberately drops index 0 of `CipherSuites` and `SupportedCurves` to skip GREASE. Clients that do not send GREASE (Firefox, curl, most non-Chromium stacks) therefore lose a real cipher/curve from their fingerprint, and `SupportedPoints[:1]` keeps only the first point.
- `firewall.Connections` is keyed by `conn.RemoteAddr().String()` (`core/firewall/fingerprint.go:60`, `general.go:40`) and cleaned only on `StateHijacked`/`StateClosed` (`general.go:44-48`). Any connection state the Go server does not surface leaks an entry, and the key is IP:port so it is unusable for HTTP/2 multiplexed or Cloudflare-fronted traffic.
- `server.ReloadConfig()` (`core/server/monitor.go:401`) is a hand-maintained duplicate of `config.Load()` and has already drifted: no `CHANGE_ME` validation, no `AdminSecret`/`APISecret` refresh, no `RatelimitWindow` clamp, no fingerprint refresh, no `"debug"` domain re-registration, and — critically — no `Stage2Difficulty` default (`init.go:167-169` has it, `monitor.go:507-526` does not), so reloaded domains get difficulty 0. The comment at `monitor.go:400` explains it lives in `server` because `config` imports `server` for `server.RoundTripper` (`init.go:130`).
- `ReloadConfig` unconditionally indexes `domains.Domains[0]` at `core/server/monitor.go:530`; a config.json edited down to zero domains panics on reload.
- Two divergent copies of the add-domain dialogue exist: `config.AddDomain` (`core/config/generate.go:62`) which prompts for `Stage2Difficulty`, and `utils.AddDomain` (`core/utils/domain.go:11`) which does not. The TUI `add` command calls the `utils` one (`core/server/monitor.go:350`), so domains added at runtime never get a difficulty written to config.json.
- `examples/config.json:4` contains `"maxLogLength": 5`, but `domains.Proxy` (`core/domains/domain.go:94-103`) has no such field — it is silently dropped. `proxy.MaxLogLength` is derived purely from terminal height at `core/server/monitor.go:73-78`.
- `examples/config.json` has no `ratelimit_time` key, so `RatelimitWindow` decodes as 0 and is clamped to **10** seconds at `core/config/init.go:92-94`, overriding the 120 default in `core/proxy/proxy.go:45`. Meanwhile the bucket pre-allocation loop at `core/server/monitor.go:581` still walks a fixed 120-second span regardless of the configured window.
- `generateOTPSecrets` (`core/server/monitor.go:639-659`) loops hourly but derives the OTP from `time.Now().Format("2006-01-02")` — a date, not an hour — so the secret only actually rotates at midnight despite the comment at `monitor.go:646` claiming hourly rotation.
- `clearProxyCache` (`core/server/monitor.go:533-573`) holds `firewall.Mutex.Lock()` — the same global lock the request hot path uses — while ranging over both `sync.Map` caches. It also computes `imgCachelen` at `monitor.go:559-563` and never uses it, and its eviction condition `(cpu < 15 && mem > 25) || mem > 95` means caches are *not* cleared while under load, which is exactly when they grow.
- One global `firewall.Mutex` (`core/firewall/general.go:10`) guards `domains.DomainsData`, all six ratelimit maps, and `firewall.Connections`. ## Request hot path: TLS handshake → server.Middleware → challenge stage machine → ReverseProxy → backend (upstream balooProxy, module `goProxy`, go 1.19)

Every inbound request is handled by the single function `server.Middleware` (core/server/middleware.go:30-364), registered as the bare `http.HandlerFunc` on the `:443` TLS server (origin mode) or the `:80` server (Cloudflare mode) in `server.Serve` (core/server/serve.go:31-116). There is no router, no per-request struct, and no `defer recover()` — the panic handler is explicitly disabled in the hot path (middleware.go:32). One process-global `sync.RWMutex`, `firewall.Mutex` (core/firewall/general.go:177), guards *all* mutable shared state: the per-domain counter map `domains.DomainsData`, the four ratelimit maps, and the TLS-fingerprint map `firewall.Connections`. A normal bypassing request acquires it 4 times (2 read + 2 write); a challenged request up to 6 times. Per-domain immutable-ish settings live in `domains.DomainsMap` (`sync.Map`) and the challenge caches in `firewall.CacheIps` / `firewall.CacheImgs` (`sync.Map`). The challenge state machine is driven by an integer "suspicion level" (`susLv`) that starts at `domainData.Stage` (1/2/3, escalated by the monitor goroutine on RPS thresholds) and can be raised/lowered/set by gofilter firewall rules; each level maps to a different secret (`proxy.CookieOTP` / `JSOTP` / `CaptchaOTP`) hashed over the same access key, and the client proves it passed by presenting a cookie whose value equals that hash. If the cookie matches, the request is logged, four `proxy-*`/`x-real-ip` headers are appended, and `domainSettings.DomainProxy.ServeHTTP` (a `httputil.NewSingleHostReverseProxy` built at config load, core/config/init.go:126-130) hands it to the custom `server.RoundTripper` (serve.go:118-196) and out to the backend over a single shared `http.Transport` with `InsecureSkipVerify: true`.

### Gotchas

- ONE global lock for everything. `firewall.Mutex` (core/firewall/general.go:177) guards DomainsData, all six ratelimit maps, and Connections. A bypassing request takes it 4 times (RLock middleware.go:40, RLock :76, Lock :88, Lock :306); a challenged one 5-6 times (plus :129 and :216). Acquisitions are never nested, so there is no ordering hazard, but the same mutex is also held by the monitor for the whole domain sweep (monitor.go:88-92), by the 5 s window rebuild (monitor.go:579-630) and by the 2 min cache sweep (monitor.go:539-570), each of which walks every window map while every request thread blocks.
- `firewall.WindowAccessIps[proxy.Last10SecondTimestamp][ip]++` (middleware.go:96) writes into a nested map that is pre-created only by `evaluateRatelimit` every 5 s (monitor.go:581-594). If that goroutine ever lags past the prefilled 120 s horizon, the inner map is nil and the increment panics *while holding the write lock*. The removed debug code and comment at middleware.go:89-95 document exactly this failure.
- `proxy.Last10SecondTimestamp`, `proxy.CurrHourStr`, `proxy.LastSecondTimeFormated` (proxy/proxy.go:53-57) are plain ints/strings written by the monitor goroutine (monitor.go:213-218) and read by every request thread with no synchronisation. Same for `proxy.CookieOTP`/`JSOTP`/`CaptchaOTP` (written monitor.go:653-655) and the `domains.Config` pointer (replaced by `json.NewDecoder(file).Decode(&domains.Config)` in ReloadConfig, monitor.go:410, while requests deref `domains.Config.Proxy.Cloudflare` at middleware.go:59).
- `firewall.KnownFingerprints`, `BotFingerprints` and `ForbiddenFingerprints` are read lock-free at middleware.go:84-85 and :135 with a comment claiming READONLY (fingerprint.go:320), but `config.GetFingerprints` overwrites all three at startup (config/init.go:104-106) by fetching JSON from raw.githubusercontent.com.
- In Cloudflare mode the client IP is `request.Header.Get("Cf-Connecting-Ip")` (middleware.go:61) with no check that the socket peer is actually Cloudflare — any direct connection to the origin can set it freely, and that value is the key for every ratelimit bucket, the cache key, the log row, and the `x-real-ip` sent to the backend.
- In origin mode `ip = strings.Split(request.RemoteAddr, ":")[0]` (middleware.go:73). For an IPv6 peer (`[2001:db8::1]:54321`) this returns the literal `"["`, so every IPv6 client shares one ratelimit bucket and one challenge-token cache entry.
- Cloudflare mode sets `browser = "Cloudflare"` (middleware.go:64), so the `if browser == ""` guard at :122 is never true: the unknown-fingerprint ratelimit (R3) and the `WindowUnkFps` counter are dead in the deployment mode that is actually used.
- Ratelimit decisions read `AccessIps`/`AccessIpsCookie`/`UnkFps` (middleware.go:69-80), which are aggregate snapshots rebuilt only every 5 s by `evaluateRatelimit` (monitor.go:597-629). The live per-bucket counters (`Window*`) are written but never read on the hot path, so a client's observed rate can lag reality by up to 5 seconds.
- The challenge pass check is a substring test on the whole Cookie header: `strings.Contains(request.Header.Get("Cookie"), "__bProxy_v="+encryptedIP)` (middleware.go:214). It does not parse cookies, does not bind to a specific stage cookie name, and matches `_1__bProxy_v`, `_2__bProxy_v`, `_3__bProxy_v` and `<ip>_3__bProxy_v` alike — a token minted for one stage satisfies the check for any stage that derives the same `encryptedIP`.
- The stage-1 cookie is set without HttpOnly (`Set-Cookie: _1__bProxy_v=...; SameSite=Lax; path=/; Secure`, middleware.go:225), and none of the `*__bProxy_v` cookies are stripped before `DomainProxy.ServeHTTP` (middleware.go:363), so the backend receives the challenge tokens.
- `RoundTripper.RoundTrip` returns a `Response` whose Body is `io.NopCloser(bytes.NewReader(buffer.Bytes()))` (serve.go:148 and :191) while `defer bufferPool.Put(buffer)` (serve.go:122) has already returned that same buffer to the shared pool. The ReverseProxy copies the body after RoundTrip returns, so a concurrent request that draws the same buffer and writes into it can corrupt the error page mid-flight.
- Backend failures and backend 5xx are both rewritten to `StatusCode: http.StatusOK` (serve.go:147 and :190), and the upstream 5xx body is interpolated raw into an `iframe srcdoc="..."` attribute (serve.go:174-176) with no escaping.
- `getTripperForDomain` (serve.go:212-219) stores the *same* `defaultTransport` pointer for every domain, so the per-domain map buys nothing and all backends share `MaxIdleConns: 10` / `MaxConnsPerHost: 10` — a hard concurrency ceiling to the origin. It also sets `InsecureSkipVerify: true` (serve.go:206) for every backend TLS connection.
- `config.Load` sets `Stage2Difficulty` when creating DomainsData (init.go:167-175, defaulting 0→5), but `ReloadConfig` (monitor.go:507-526) rebuilds the same struct **without** that field. After the `reload` or `add` terminal command, `domainData.Stage2Difficulty` is 0, so `publicSalt := encryptedIP[:len(encryptedIP)-0]` (middleware.go:229) is the entire hash and the stage-2 proof-of-work becomes trivial. `ReloadConfig` also resets Stage, TotalRequests and all counters for every domain.
- The synthetic `"debug"` domain exists in `DomainsData` with `Stage: 0` (config/init.go:200-201) and in `DomainsMap` with only `Name` set (init.go:195-197), i.e. `DomainProxy == nil`. A request with `Host: debug` passes the domain lookup, gets susLv 0 (whitelisted, no challenge), and reaches `domainSettings.DomainProxy.ServeHTTP` at middleware.go:363 on a nil `*httputil.ReverseProxy`.
- `domains.DomainsMap.Load(domainName)` at middleware.go:145 is type-asserted without the `ok` form, and the value copied out is a whole `DomainSettings` including a `tls.Certificate` — a substantial per-request struct copy on the hot path. The same unchecked pattern appears in `checkAttack` (monitor.go:132-133).
- Every block/ratelimit/challenge response is written with an implicit HTTP 200 (`SendResponse`, middleware.go:25-28, only ever calls `writer.Write`). Nothing in the hot path returns 403, 429 or 503.
- `/_bProxy/stats` and `/_bProxy/fingerprint` (middleware.go:325-332) are unauthenticated and expose per-domain stage, request volume, r/s and the client's TLS fingerprint. The v1 API path embeds `proxy.AdminSecret` in the URL (`/_bProxy/<secret>/api/v1`, :337), which leaks through access logs and Referer, and when its `proxy-secret` header check fails `api.Process` returns false so the request continues on to the backend rather than being rejected.
- `utils.AddLogs` (text.go:65-69) appends to `domainData.LastLogs` on every bypassing request with no cap. Trimming happens only inside `ReadLogs` (text.go:85-94) and only for `proxy.WatchedDomain`, so every non-watched domain's log slice grows without bound.
- The captcha is rendered synchronously inside the request (middleware.go:242-287): two 100x37 RGBA images, a warp pass, up to 29 triangles, two PNG encodes and two base64 encodes, all driven by the unseeded package-global `math/rand`. `firewall.CacheImgs` has no TTL — `clearProxyCache` (monitor.go:552-569) only bulk-empties both caches when `cpu < 15 && mem > 25` or `mem > 95`, i.e. never while under load.
- `Middleware` deliberately has no panic recovery (the `defer pnc.PanicHndl()` is commented out at middleware.go:32 "to avoid overhead"), so hot-path panics fall through to net/http's per-connection recover.
- The stage-2 page loads its proof-of-work library from `cdn.jsdelivr.net/gh/41Baloo/balooPow@main` and crypto-js from cdnjs (middleware.go:232) — the challenge cannot be solved if either third-party CDN is unreachable from the client.
- `firewall.Fingerprint` drops index 0 of `CipherSuites` and `SupportedCurves` (fingerprint.go:375-381) to shed GREASE values, which silently discards a legitimate cipher/curve for clients that do not send GREASE, and it reads `SupportedPoints[:1]` (:385) — the first element, not the rest — inconsistently with the other two loops.

## Firewall rule DSL, sliding-window ratelimiting, TLS fingerprinting, and challenge/crypto primitives (core/firewall + core/utils)

The firewall subsystem is three loosely coupled parts sharing one global `sync.RWMutex` (`firewall.Mutex`, core/firewall/general.go:10). (1) A Wireshark-style display-filter DSL supplied by `github.com/kor44/gofilter`: field names are registered once in an `init()` (core/firewall/filter.go:5-34), rule expressions are parsed to an AST at config-load time (core/config/init.go:115), and evaluated per request by walking every rule in order and folding an integer "suspicion level" (core/firewall/eval.go:10-49). (2) A sliding-window ratelimiter built from 10-second buckets (`Window*` maps, core/firewall/general.go:13-25) that a background goroutine flattens into flat lookup maps (`AccessIps`, `AccessIpsCookie`, `UnkFps`) every 5 seconds (core/server/monitor.go:576-637); the request hot path only reads the flattened maps, so ratelimit state is up to 5 s stale. (3) TLS fingerprinting via `tls.Config.GetConfigForClient` (core/server/serve.go:72 → core/firewall/fingerprint.go:52), which builds a comma-separated hex string from the ClientHello and stores it in `Connections[RemoteAddr]`; the middleware looks that string up in three hardcoded maps (`KnownFingerprints`, `BotFingerprints`, `ForbiddenFingerprints`, core/firewall/fingerprint.go:12/28/47), optionally overwritten at startup from GitHub. The suspicion level selects one of four challenge stages, each keyed by a per-stage token derived with BLAKE3 (`utils.Encrypt`) over an OTP secret that is itself SHA-256 (`utils.EncryptSha`) of a config secret plus the current date; stage 2 is a SHA-256 proof-of-work solved by a CDN-loaded JS library, stage 3 is a locally generated warped PNG captcha whose answer is the first 6 hex characters of the same token.

### Control and data flow

1) TLS handshake (origin mode only). `serve.go:71-75` sets `TLSConfig.GetConfigForClient = firewall.Fingerprint` on the :443 server. `firewall.Fingerprint` (core/firewall/fingerprint.go:52-87) closes the connection and returns `(nil, nil)` if `len(clientHello.CipherSuites) == 0` (fingerprint.go:55-58); otherwise it builds `fingerprint` by appending `fmt.Sprintf("0x%x,", …)` for `CipherSuites[1:]` (fingerprint.go:66-68), `SupportedCurves[1:]` (fingerprint.go:71-73), and `SupportedPoints[:1]` (fingerprint.go:76-78) — i.e. index 0 of ciphers and curves is dropped as presumed GREASE, and only the FIRST EC point format is taken. It stores `Connections[conn.RemoteAddr().String()] = fingerprint` under `Mutex.Lock` (fingerprint.go:82-84) and always returns `(nil, nil)`, so the base TLS config is kept. Entries are deleted on `http.StateHijacked`/`http.StateClosed` by `firewall.OnStateChange` (core/firewall/general.go:38-49), wired as `ConnState` on both origin-mode servers (serve.go:60, serve.go:69). In Cloudflare mode the :80 server has no `ConnState` and no `GetConfigForClient` (serve.go:37-44), so no fingerprint is ever recorded.

2) Request entry. `server.Middleware` (core/server/middleware.go:30) looks up `domains.DomainsData[request.Host]` under `Mutex.RLock` (middleware.go:40-42) and 404s if absent. Branch on `domains.Config.Proxy.Cloudflare` (middleware.go:59): Cloudflare mode takes the client IP verbatim from the `Cf-Connecting-Ip` header and hardcodes `tlsFp = browser = "Cloudflare"`, `fpCount = 0` (middleware.go:61-71); origin mode takes `strings.Split(request.RemoteAddr, ":")[0]` and reads `Connections[request.RemoteAddr]`, `UnkFps[tlsFp]`, `AccessIps[ip]`, `AccessIpsCookie[ip]` under one `RLock` (middleware.go:73-81), then does unguarded map reads of `KnownFingerprints[tlsFp]` and `BotFingerprints[tlsFp]` (middleware.go:84-85).

3) Counter increment. Under `Mutex.Lock`: `WindowAccessIps[proxy.Last10SecondTimestamp][ip]++` plus a copy-modify-write of `DomainsData[domainName]` to bump `TotalRequests` (middleware.go:88-100).

4) Fixed ratelimit gates, evaluated before any rule. `ipCountCookie > proxy.FailChallengeRatelimit` → "(R1)" (middleware.go:108-112); `ipCount > proxy.IPRatelimit` → "(R2)" (middleware.go:115-119); if the fingerprint is not a known browser, `fpCount > proxy.FPRatelimit` → "(R3)", otherwise `WindowUnkFps[Last10SecondTimestamp][tlsFp]++` under `Mutex.Lock` (middleware.go:122-132); `ForbiddenFingerprints[tlsFp] != ""` → hard block naming the fingerprint (middleware.go:135-140).

5) Rule evaluation. `susLv` starts at `domainData.Stage` (middleware.go:105). If the domain has any compiled rules, a `gofilter.Message` (a `map[string]interface{}`) is built with 21 keys (middleware.go:151-175) and passed to `firewall.EvalFirewallRule(domainSettings, variables, susLv)` (middleware.go:177). That function iterates `currDomain.CustomRules` in slice order and, for each rule whose `Filter.Apply(variables)` is true, switches on `rule.Action[:1]`: `"+"` adds, `"-"` subtracts, anything else is parsed as an absolute value which is assigned and returned immediately, short-circuiting the remaining rules (core/firewall/eval.go:12-47). Parse failures via `fmt.Sscan` are printed and ignored, leaving `susLv` unchanged (eval.go:20-21, 30, 40). Rules were compiled once by `gofilter.NewFilter(fwRule.Expression)` at load (core/config/init.go:115) or on `reload` (core/server/monitor.go:456); a compile error `panic`s the process (init.go:117, monitor.go:458). `gofilter.Apply` walks an AST of `nodeAnd`/`nodeOr`/`nodeNot`/`nodeEq`/`nodeGt`/`nodeGe`/`nodeLt`/`nodeLe`/`nodeContains`/`nodeMatch`/`nodeExist` (gofilter nodes.go:21-661); every leaf goes through `applyRange`, which returns false when the field key is missing from the Message (gofilter nodes.go:664-668).

6) Token derivation. `accessKey = ip + tlsFp + reqUa + proxy.CurrHourStr` (middleware.go:184). `firewall.CacheIps` is consulted with `accessKey + susLvStr` (middleware.go:185). On a miss, `susLv` selects the secret: 0 = whitelist (empty token), 1 = `utils.Encrypt(accessKey, proxy.CookieOTP)`, 2 = `utils.Encrypt(accessKey, proxy.JSOTP)` plus `hashedEncryptedIP = utils.EncryptSha(encryptedIP, "")` stored under key `encryptedIP`, 3 = `utils.Encrypt(accessKey, proxy.CaptchaOTP)`, ≥4 = hard block (middleware.go:187-204). The OTPs are regenerated by `generateOTPSecrets`, which sleeps 1 hour but keys on `time.Now().Format("2006-01-02")`, so the value only actually changes at midnight (core/server/monitor.go:639-658).

7) Challenge issue / verification. Verification is a single substring test: `strings.Contains(request.Header.Get("Cookie"), "__bProxy_v="+encryptedIP)` (middleware.go:214). On failure, `WindowAccessIpsCookie[Last10SecondTimestamp][ip]++` (middleware.go:216-218) and the stage-specific challenge is served: stage 1 sets `_1__bProxy_v=<token>` and 302-redirects to the same URI (middleware.go:225-226); stage 2 splits the token into `publicSalt = encryptedIP[:len-Stage2Difficulty]` and serves an HTML page that loads `balooPow.min.js` from cdn.jsdelivr.net and `crypto-js` 4.0.0 from cdnjs, brute-forcing the missing `Stage2Difficulty` characters until `sha256(publicSalt+solution)` equals `hashedEncryptedIP`, then sets `_2__bProxy_v=<publicSalt><solution>` and reloads (middleware.go:229-232); stage 3 splits the token into `secretPart = encryptedIP[:6]` and `publicPart = encryptedIP[6:]`, renders a captcha, and the page sets `<ip>_3__bProxy_v=<typed answer><publicPart>` and probes `/_bProxy/verified` before reloading (middleware.go:235-296). Because verification is a substring match on the full `Cookie` header, a stage-3 cookie only passes when the typed answer equals `secretPart`.

8) Captcha generation (stage 3, cache miss keyed on `secretPart` in `firewall.CacheImgs`, middleware.go:240-242). A 100x37 RGBA image gets three `utils.AddLabel` calls using `basicfont.Face7x13` (core/utils/image.go:12-22): `publicPart[6:]` as a near-transparent decoy, `publicPart[:6]` as a red decoy at a random position, and `secretPart` in solid green as the answer (middleware.go:246-248). The image is sine-warped by `utils.WarpImg` with amplitude `rand.Intn(10)+10 / 10` and period `37/5` (core/utils/image.go:24-42, middleware.go:250-257). Then 10-29 triangles of size 10-14 are cut out of the captcha and drawn into a separate mask image shifted by `randomShift ∈ [-25,25)` via `utils.DrawTriangle`, which zeroes the source pixel and records it in a blacklist so no pixel is moved twice (core/utils/image.go:44-56, middleware.go:262-272). Both images are PNG-encoded, base64'd, cached as a `[2]string` (middleware.go:274-287) and embedded as data URIs into two stacked canvases; the client slider re-offsets the mask to realign the cut-out triangles.

9) Pass-through. On success the request is logged via `utils.AddLogs` under `Mutex.Lock`, `BypassedRequests` is incremented (middleware.go:306-320), reserved `/_bProxy/*` paths are handled (middleware.go:324-355), the headers `x-real-ip`, `proxy-real-ip`, `proxy-tls-fp`, `proxy-tls-name` are added (middleware.go:358-361), and the request is forwarded to `domainSettings.DomainProxy` (middleware.go:363).

10) Window maintenance (`evaluateRatelimit`, core/server/monitor.go:576-637, loops every 5 s). Under `Mutex.Lock` it pre-creates the next 12 buckets (`i` from `Last10SecondTimestamp` to `+120`, step 10) for all three window maps so the hot path can index them without a nil check (monitor.go:581-594). It then rebuilds `AccessIps`, `AccessIpsCookie` and `UnkFps` from scratch, deleting any bucket where `utils.TrimTime(windowTime)+proxy.RatelimitWindow < proxy.LastSecondTimestamp` and summing the rest (monitor.go:597-629). `proxy.Initialised = true` is set here, which is what `main.go:43-45` blocks on before serving. `proxy.Last10SecondTimestamp` itself is refreshed once per second by `printStats` (monitor.go:213-218) using `utils.TrimTime` (core/utils/text.go:168-170), which floors a Unix second to a multiple of 10.

### Gotchas

- Ratelimit decisions lag by up to 5 seconds. The hot path reads only the flattened maps AccessIps/AccessIpsCookie/UnkFps (core/server/middleware.go:69-70, 78-80), which are rebuilt from scratch once per iteration of evaluateRatelimit (core/server/monitor.go:597-629) with a trailing `time.Sleep(5 * time.Second)` (monitor.go:634). Writes go to the Window* buckets, which are never read on the request path.
- The middleware writes to `firewall.WindowAccessIps[proxy.Last10SecondTimestamp]` without a nil check (core/server/middleware.go:96, and the same pattern at :130 and :217). The buckets are pre-created 120 s ahead by evaluateRatelimit (monitor.go:581-594). The commented-out block at middleware.go:92-95 documents the failure mode the authors saw: if that goroutine falls behind, the map index panics inside a held Mutex.Lock.
- `fmt.Sprintf("0x%x", curve)` on a `tls.CurveID` hex-encodes the ASCII of its String() method, not the numeric ID — verified with go1.25.4: X25519 renders as `0x583235353139` ("X25519") and CurveP256 as `0x437572766550323536` ("CurveP256"), while cipher suites (plain uint16) render numerically as `0x1301`. So the fingerprint string (core/firewall/fingerprint.go:66-78) silently mixes two encodings, and any Go version that renames a curve's String() output invalidates every stored fingerprint.
- Fingerprint construction drops `CipherSuites[0]` and `SupportedCurves[0]` unconditionally as presumed GREASE (core/firewall/fingerprint.go:66, 71), but takes `SupportedPoints[:1]` — the first element, not a skip (fingerprint.go:76). Clients that do not send GREASE lose a real cipher and a real curve from their fingerprint.
- In Cloudflare mode all fingerprinting is disabled by construction: tlsFp/browser are set to the literal "Cloudflare" and fpCount to 0 (core/server/middleware.go:63-66), the :80 server registers neither ConnState nor GetConfigForClient (core/server/serve.go:37-44), and `ip` is taken from the `Cf-Connecting-Ip` header with no trusted-peer check and no nil check before `net.ParseIP` (middleware.go:61, 152).
- `firewall.KnownFingerprints[tlsFp]` and `BotFingerprints[tlsFp]` are read outside any lock (core/server/middleware.go:84-85, comment at :83), while `GetFingerprints` replaces those same package-level maps wholesale at startup (core/config/init.go:104-106). It is safe only because the replacement happens before Serve() starts.
- The three `GetFingerprints` calls discard their error return (core/config/init.go:104-106). If GitHub is unreachable the process starts silently using the hardcoded maps in core/firewall/fingerprint.go:12-49, which differ from the JSON files (e.g. the JSON labels the first Chromium entry "Chromium Old").
- An absolute rule action (no leading + or -) assigns and returns immediately (core/firewall/eval.go:42-43), so rule order matters: any rule after the first matching absolute rule is never evaluated. Relative +/- rules keep accumulating through the whole list.
- Five registered DSL fields are never populated in the Message: ip.country, ip.asn, ip.requests (core/firewall/filter.go:7,8,12), http.headers and http.body (filter.go:24,25). The Message built at core/server/middleware.go:151-175 omits them, and gofilter's applyRange returns false for a missing key (gofilter nodes.go:664-668), so a rule referencing any of them parses cleanly and silently never matches.
- Typo in the error path of the "-" action: `fmt.Println` is called with a format string and arguments instead of `fmt.Printf` (core/firewall/eval.go:30), so that branch prints the literal format verb text. `go vet` flags this.
- OTP secrets are keyed on the DATE, not the hour, despite the goroutine's 1-hour sleep and the comment claiming an hourly change (core/server/monitor.go:650-657). What actually rotates hourly is `proxy.CurrHourStr`, which is folded into the accessKey (middleware.go:184) — and it is `strconv.Itoa` of the clock hour 0-23, so it repeats every day.
- `utils.Encrypt` hashes the concatenation `input + key` (core/utils/encryption.go:20), so it is not a keyed hash: Encrypt("ab","cd") and Encrypt("a","bcd") collide. `utils.EncryptSha` has the identical concat structure (encryption.go:24-28) and is used both for OTP derivation and, with an empty key, as the plain SHA-256 of the PoW target (middleware.go:195).
- `utils.RandomString` uses math/rand (core/utils/encryption.go:6,35) and no `rand.Seed` call exists anywhere in the tree, so under go1.19 semantics the global source is deterministically seeded and every generated adminsecret/apisecret/cookie/javascript/captcha secret in core/config/generate.go:23-34 is reproducible. All captcha randomness (positions, colors, warp amplitude, triangle count/size, shift) comes from the same unseeded global source (core/server/middleware.go:243-270).
- Challenge verification is a substring match against the entire Cookie header — `strings.Contains(cookieHeader, "__bProxy_v="+encryptedIP)` (core/server/middleware.go:214) — not a parsed cookie lookup. The three stages set differently-prefixed cookie names (`_1__bProxy_v`, `_2__bProxy_v`, `<ip>_3__bProxy_v` at middleware.go:225, 232, 296) that all end in the same matched suffix.
- The stage-3 captcha answer is the first 6 characters of the stage-3 token, and the remaining 58 characters are handed to the client in the clear as `publicPart` (core/server/middleware.go:235-236); the captcha image also renders `publicPart[:6]` and `publicPart[6:]` as decoy labels (middleware.go:246-247). The captcha image cache key is that same secretPart (middleware.go:240, 287).
- `clearProxyCache` only purges CacheIps/CacheImgs when `(cpu < 15 && mem > 25) || mem > 95`, evaluated every 2 minutes (core/server/monitor.go:552, 564, 571), and it parses those figures from the strings proxy.CpuUsage/proxy.RamUsage, defaulting to 0 on parse error (monitor.go:541-549). Under sustained load neither cache is ever evicted; there is no per-entry TTL despite the comments at core/firewall/general.go:27 and :31 claiming 2 minutes.
- `proxy.RatelimitWindow` is read from config and clamped to a minimum of 10 only in config.Load (core/config/init.go:92-95); ReloadConfig (core/server/monitor.go:401-531) never re-reads it, so the `reload` command cannot change the window size. Default is 120 seconds (core/proxy/proxy.go:45).
- Two configured knobs are dead: `proxy.FailRequestRatelimit` ("noRequestsSent") is assigned at core/config/init.go:100 and core/server/monitor.go:447 but never read, and `proxy.JSDifficulty` (core/proxy/proxy.go:30) is shadowed by the per-domain `Stage2Difficulty` actually used at middleware.go:229/232. `utils.HashToInt` (core/utils/encryption.go:40) and `firewall.RequestLog` (core/firewall/requests.go:5) have no callers or references at all.
- `ReloadConfig` rebuilds DomainsData without setting Stage2Difficulty (core/server/monitor.go:507-526), while config.Load defaults it to 5 when zero (core/config/init.go:167-169). After a `reload`, Stage2Difficulty is 0 for every domain, making `publicSalt` the entire token (middleware.go:229) and the PoW trivially empty.
- `domains.DomainData` is a value type stored in a plain map, so every counter bump is a copy-modify-write of the whole struct under Mutex.Lock (core/server/middleware.go:97-99, 317-319; core/server/serve.go:93-97). `checkAttack` additionally writes back into `domains.DomainsData` (monitor.go:208) while Monitor is ranging over that same map (monitor.go:89-91).
- `utils.AddLogs`, `ReadLogs` and `ClearLogs` are documented "Only run in locked thread" (core/utils/text.go:21, 35, 67), but ReadLogs takes firewall.Mutex.RLock/Lock itself (text.go:37-39, 48-50) — it is called from printStats, which is not holding firewall.Mutex, whereas AddLogs is called from middleware.go:307 while the caller holds Mutex.Lock.
- Log truncation is byte-based on a string containing ANSI escape sequences (`parsedOut[:len(parsedOut)-(len(parsedOut)+4-proxy.TWidth)]`, core/utils/text.go:59), so it can slice mid-escape or mid-UTF-8 rune. The log entry itself carries the raw client user-agent and path (middleware.go:307-315) into terminal output with no escaping.
- Both fingerprint eviction paths hinge on `conn.RemoteAddr().String()` matching between the handshake (core/firewall/fingerprint.go:60) and the ConnState hook (core/firewall/general.go:40), while the lookup uses `request.RemoteAddr` (middleware.go:77). Only StateHijacked and StateClosed delete; StateNew is an empty case (general.go:43) and StateActive/StateIdle are unhandled.
- gofilter's RegisterField uses `if exists := fieldNameToIdMap[name]; exists != 0` (gofilter filter_info.go:53) against a package-global monotonically increasing id, and NewFilter reports errors through a lexer error string (filter_main.go:25-33). Field types are fixed at registration: comparing an FT_INT field against a quoted string, or an FT_STRING field against a bare token, is resolved at parse time by checkFieldNameVsTypeValue (gofilter parser.y) and fails the whole rule compile, which panics the process at core/config/init.go:117.

## Ops surface — admin API, terminal UI/monitor loop, config hot-reload, panic handling, Discord/quickchart alerting, and runtime external endpoints (upstream balooProxy @ 4d4f128, module `goProxy`, go 1.19)

Operations on this proxy happen through three disjoint channels, none of which is a conventional admin server. (1) A read-mostly JSON admin API is bolted into the request middleware itself: `api.Process` (v1) and `api.ProcessV2` (v2) are reached only as reserved paths on a normal proxied domain (`core/server/middleware.go:337`, `core/server/middleware.go:350`), sit *behind* the full challenge/ratelimit stack, and authenticate on a single shared static secret sent as the `proxy-secret` / `Proxy-Secret` header (`core/api/api.go:17`, `core/api/api.go:155`). v1 additionally requires `proxy.AdminSecret` embedded in the URL path. The API mutates almost nothing — the only state-changing actions are `FILL_IP_CACHE` (a load-test that writes 19 980 junk entries into the IP cache, `core/api/api.go:102`) and `RELOAD`, which is a lock/unlock no-op (`core/api/api.go:110`). (2) The real control plane is the interactive terminal: `server.Monitor` repaints an ANSI-positioned HUD once per second (`core/server/monitor.go:66`, sleep at `:97`) while `server.commands` reads stdin and implements `stage`, `domain`, `add`, `clrlogs`, `reload`, `help` (`core/server/monitor.go:286`). (3) Config hot-reload is `server.ReloadConfig` (`core/server/monitor.go:401`), invoked only from the `add` and `reload` commands — it re-reads `config.json`, recompiles every gofilter rule, rebuilds each reverse proxy and certificate, and resets all per-domain counters to zero. Panics are logged to `crash.log` by `pnc.PanicHndl` and then re-raised, so any caught panic still terminates the process (`core/pnc/panicHandler.go:30`). Alerting is Discord-webhook only, with attack graphs rendered by uploading the chart config to quickchart.io (`core/utils/discord.go:201`). At runtime the proxy itself contacts exactly three external hosts: raw.githubusercontent.com (fingerprints + version check, startup only), quickchart.io, and whatever Discord webhook URL the operator configured.

### Control and data flow

ADMIN API (v1)
1. Request arrives at `server.Middleware` (`core/server/middleware.go:29`) and runs the entire mitigation stack first: domain lookup, ratelimit checks, firewall rules, cookie/JS/captcha challenge.
2. Only after the request is counted as "bypassed" (`core/server/middleware.go:305-320`) does control reach the reserved-path switch (`core/server/middleware.go:325`). Consequence: the API is unreachable unless the caller passes the current challenge stage, and every API call increments `TotalRequests` and `BypassedRequests` and is written into the domain's terminal log ring.
3. `case "/_bProxy/" + proxy.AdminSecret + "/api/v1"` (`core/server/middleware.go:337`) calls `api.Process(writer, request, domainData)`.
4. `api.Process` (`core/api/api.go:15`) compares `request.Header.Get("proxy-secret")` to `proxy.APISecret` (`core/api/api.go:17`). Mismatch returns `false`, the switch case does NOT return, and the request falls through to `domainSettings.DomainProxy.ServeHTTP` (`core/server/middleware.go:365`) — i.e. an unauthenticated hit on the admin path is proxied to the backend.
5. On success it reads the whole body with `io.ReadAll` (no size limit, `core/api/api.go:21`) and JSON-decodes `{"domain":..., "action":...}` (`core/api/structs.go:10`).
6. Empty `domain` -> `handleProxyActions` (`core/api/api.go:57`); non-empty -> `domains.DomainsMap.Load(domain)` then `handleDomainActions` (`core/api/api.go:120`) using the *caller's* `domainData` snapshot, not the requested domain's.
7. `APIResponse` (`core/api/api.go:194`) marshals `{"success":bool,"results":{...}}` and writes it with `fmt.Fprint`.

ADMIN API (v2)
1. `strings.HasPrefix(path, "/_bProxy/api/v2")` (`core/server/middleware.go:350`) -> `api.ProcessV2` (`core/api/api.go:153`). No AdminSecret in the path; header check only (`core/api/api.go:155`).
2. Path is trimmed of `/_bProxy/api/v2/` and split (`core/api/api.go:159-160`). One segment = proxy-level action; two segments = `/<domain>/<action>`, with `domains.DomainsData[domain]` read under `firewall.Mutex.RLock` (`core/api/api.go:185-187`).

ACTION SET (both versions share the handlers)
- Proxy-level (`core/api/api.go:57-118`): `GET_PROXY_STATS`, `GET_PROXY_STATS_CPU_USAGE`, `GET_PROXY_STATS_RAM_USAGE`, `GET_IP_REQUESTS` (dumps the full per-IP request map), `GET_FINGERPRINT_REQUESTS` (dumps unknown-fingerprint counters), `GET_IP_CACHE` (dumps the entire encrypted-IP cache via `firewall.CacheIps.Range`), `FILL_IP_CACHE`, `RELOAD`.
- Domain-level (`core/api/api.go:120-151`): `GET_TOTAL_REQUESTS`, `GET_BYPASSED_REQUESTS`, `GET_TOTAL_REQUESTS_PER_SECOND`, `GET_BYPASSED_REQUESTS_PER_SECOND`, `GET_FIREWALL_RULES` (returns raw config rules), `GET_LOGS` (returns `LastLogs`: time, client IP, browser/bot/TLS fingerprint, user-agent, full request path).
- Unrecognised action -> `ERR_ACTION_NOT_FOUND` (`core/api/structs.go:5`).

UNAUTHENTICATED RESERVED PATHS (same switch, no secret required, still behind the challenge)
- `/_bProxy/stats` (`core/server/middleware.go:325`) — stage, total/bypassed counters, r/s, and the build `proxy.Fingerprint` UUID.
- `/_bProxy/fingerprint` (`core/server/middleware.go:329`) — caller's IP, its request/challenge counters, susLv, raw TLS fingerprint, browser/bot label.
- `/_bProxy/verified` (`core/server/middleware.go:333`) — returns literal `verified`; polled by the captcha page JS.
- `/_bProxy/credits` (`core/server/middleware.go:344`) — GPL attribution string.

TERMINAL UI LOOP
1. `main` starts `server.Monitor` as a goroutine, then blocks until `proxy.Initialised` (`main.go:42-45`); that flag is only set inside `evaluateRatelimit` (`core/server/monitor.go:631`), so the ratelimit worker is the startup gate.
2. `Monitor` (`core/server/monitor.go:34`) clears the screen, seeds the time globals (`:43-48`), then spawns four workers: `commands` (`:51`), `clearProxyCache` (`:54`), `generateOTPSecrets` (`:57`), `evaluateRatelimit` (`:60`).
3. Main loop, once per second (`core/server/monitor.go:66-98`): take `PrintMutex`, re-measure the terminal with `term.GetSize` and recompute `proxy.MaxLogLength = height-15` (`:68-78`), clear the pane, take `firewall.Mutex.Lock` and run `checkAttack` over every domain (`:88-92`), then `printStats` (`:94`), release, `time.Sleep(1 * time.Second)` (`:97`).
4. `checkAttack` (`core/server/monitor.go:102`) computes per-second deltas from `TotalRequests-PrevRequests`, tracks peaks, appends a `RequestLog` sample while `BufferCooldown > 0`, and runs the stage machine: stage1->2 when bypassed r/s > `BypassStage1` (`:149`), 2->3 when > `BypassStage2` (`:168`), 3->2 and 2->1 on the `Disable*` thresholds (`:172`, `:179`). Entering an attack fires `go utils.SendWebhook(..., 0)` (`:161`, `:197`) and sets `BufferCooldown = 10`; the countdown reaching 0 fires `go utils.SendWebhook(..., 1)` and clears the peaks and `RequestLogger` (`:138-143`). The whole block is skipped when `StageManuallySet` is true and the cooldown has expired (`:114`).
5. `printStats` (`core/server/monitor.go:211`) refreshes the shared time globals, samples CPU with `gopsutil` `cpu.Percent(0,false)` into `proxy.CpuUsage` (`:220-230`), computes `proxy.RamUsage` as `MemStats.Alloc/MemStats.Sys*100` (`:234-238`), then prints domain/stage/lock/total/bypassed and calls `utils.ReadLogs` (`:280`), which truncates `LastLogs` to `MaxLogLength` and paints each row with absolute cursor moves (`core/utils/text.go:36-65`).
6. `commands` (`core/server/monitor.go:286`) reads stdin with a `bufio.Scanner`; `stage N` locks the stage (`:307`), `domain [name]` switches `proxy.WatchedDomain` (`:335`), `add` runs the interactive `utils.AddDomain` dialogue and then `ReloadConfig` (`:347-356`), `clrlogs` empties `LastLogs` (`:357`), `reload` calls `ReloadConfig` (`:375-379`), `help` flips `helpMode` so the HUD renders the command list (`:259-267`).

CONFIG HOT-RELOAD
1. `ReloadConfig` (`core/server/monitor.go:401`) resets `domains.Domains`, opens `config.json` and decodes it straight over `domains.Config` (`:405-410`) — decode errors are discarded.
2. Re-applies `cloudflare`, the three challenge secrets, the four timeouts, terminal colors and the four ratelimits (`:412-447`). Note it does NOT re-read `adminsecret`, `apisecret`, or `ratelimit_time`, and does not enforce the `CHANGE_ME` checks that `config.Load` applies at startup (`core/config/init.go:41-63`).
3. Per domain: recompiles every firewall expression with `gofilter.NewFilter` (panics on a bad rule, `:456-459`), builds a fresh `httputil.NewSingleHostReverseProxy` with a `&RoundTripper{}` (`:467-471`), loads the X509 keypair unless in Cloudflare mode (panics on failure, `:473-480`), stores the new `DomainSettings` in `domains.DomainsMap` (`:482`), and overwrites `domains.DomainsData[name]` with a zeroed struct under `firewall.Mutex` (`:506-527`) — all counters, logs, stage and attack state are lost on every reload.
4. Finally forces `proxy.WatchedDomain = domains.Domains[0]` (`:530`).
5. Startup path is the parallel `config.Load` (`core/config/init.go:25`), which additionally refuses to boot on `CHANGE_ME` secrets, registers a synthetic `"debug"` domain with Stage 0 (`core/config/init.go:195-220`), and runs `VersionCheck` (`:224`).

PANIC HANDLING
1. `main` opens `crash.log` once for a deferred close (`main.go:21-25`) and `pnc.InitHndl` opens it a second time into the package-level `logFile` (`core/pnc/panicHandler.go:14-21`). `log.SetOutput(io.Discard)` disables the standard logger entirely (`main.go:32`).
2. `pnc.PanicHndl` (`core/pnc/panicHandler.go:23`) is a deferred recover: it allocates a 4 096 000-byte buffer, captures only the current goroutine's stack (`runtime.Stack(stackTrace, false)`), appends a timestamped entry to `crash.log`, then re-panics (`:30`).
3. It is deferred in `main` (`main.go:29`), `Monitor` (`core/server/monitor.go:36`), `commands` (`:288`), `clearProxyCache` (`:535`), `generateOTPSecrets` (`:641`), `Serve` and its TLS goroutine (`core/server/serve.go:33`, `:106`) and `SendWebhook` (`core/utils/discord.go:28`). It is deliberately absent from the request hot path (`core/server/middleware.go:31`) and absent from `evaluateRatelimit`.
4. `pnc.LogError` (`core/pnc/panicHandler.go:34`) exists but has no callers.

DISCORD + QUICKCHART
1. `checkAttack` fires `go utils.SendWebhook(domainData, domainSettings, 0|1)` (`core/server/monitor.go:139`, `:161`, `:197`).
2. `SendWebhook` (`core/utils/discord.go:26`) returns immediately if the domain has no webhook URL (`:30`).
3. Type 0 (attack start) builds an embed titled "DDoS Alert" with current total and allowed r/s (`:41-62`). The description runs through `InitPlaceholders` (`core/utils/discord.go:16`), which substitutes `{{domain.name}}`, `{{attack.start}}` (first `RequestLogger` sample), `{{attack.end}}` (last sample), `{{proxy.cpu}}`, `{{proxy.ram}}`.
4. Type 1 (attack over) serialises the whole `RequestLogger` into three Chart.js datasets (bypassed, total, CPU) by string concatenation (`:68-81`), embeds them in a hand-written Chart.js v2.9.4 config (`:83-200`), and calls `quickchartgo.New()` + `qc.GetShortUrl()` (`:201-207`).
5. `GetShortUrl` POSTs the chart JSON to `https://quickchart.io:443/chart/create` with a 10 s client timeout and returns a `https://quickchart.io/chart/render/...` URL, which is set as the embed image (`:229-231`). If the chart call errors, `webhookContent` stays zero-valued and an empty embed is still POSTed.
6. The payload is POSTed to the operator's Discord webhook URL with a bare `&http.Client{}` — no timeout — and the response and error are discarded (`core/utils/discord.go:243-249`).

### Gotchas

- The admin API is not on a separate listener or port — it is a `switch` case inside the request hot path (`core/server/middleware.go:325-357`), so it inherits the full challenge stack. An operator whose IP is ratelimited or whose client fails the JS/captcha challenge cannot reach the API at all, and every API call inflates that domain's TotalRequests/BypassedRequests counters and pollutes the terminal log ring.
- Failed API auth is fail-open into the proxy, not fail-closed. `api.Process` returns `false` on a secret mismatch (`core/api/api.go:17-19`) and the `case` at `core/server/middleware.go:337-342` has no `return` for that branch — the request continues to `domainSettings.DomainProxy.ServeHTTP` (`core/server/middleware.go:365`) and is forwarded to the backend. Same for v2 (`core/server/middleware.go:350-355`).
- v1 puts `proxy.AdminSecret` in the URL path (`core/server/middleware.go:337`), so it lands in access logs, Referer headers and any CDN/proxy in front. v2 drops the path secret entirely and relies only on the `Proxy-Secret` header (`core/api/api.go:155`) — the two versions have different effective auth strength against the same backing secret.
- `api.Process` looks up the requested domain's `DomainSettings` but then passes the *caller's* `domainData` (the Host the request arrived on) into `handleDomainActions` (`core/api/api.go:44-53`). So `GET_TOTAL_REQUESTS`/`GET_LOGS` for domain A, requested via domain B's Host header, return B's counters and B's logs with A's firewall rules. `ProcessV2` does this correctly (`core/api/api.go:185-189`).
- `FILL_IP_CACHE` is a load-test action reachable by anyone holding the API secret: it writes 19 980 random entries into `firewall.CacheIps` while holding the global `firewall.Mutex` write lock (`core/api/api.go:102-108`), stalling every in-flight request.
- The `RELOAD` action does nothing — it takes and releases `firewall.Mutex` and falls through without calling `APIResponse` (`core/api/api.go:110-112`), returning a 200 with an empty body. Config reload is only available from the terminal `reload` command.
- `ReloadConfig` zeroes every domain's `DomainsData` (`core/server/monitor.go:506-527`): stage, manual stage lock, attack flags, all counters and all logs are discarded on every reload, and any domain removed from config.json keeps a stale entry in `DomainsMap`/`DomainsData` because neither is cleared first.
- `ReloadConfig` skips the `CHANGE_ME` validation and never re-reads `adminsecret`, `apisecret` or `ratelimit_time` (compare `core/server/monitor.go:412-447` with `core/config/init.go:38-100`). Rotating the API secret requires a full restart; the challenge secrets, in contrast, do reload live and instantly invalidate every outstanding challenge cookie.
- `ReloadConfig` decodes straight into `domains.Config` and discards the decode error (`core/server/monitor.go:410`). Malformed JSON leaves a partially-overwritten live config. A bad firewall expression or an unloadable certificate instead panics inside the reload (`:458`, `:478`), which `PanicHndl` re-raises — a typo in config.json kills the proxy.
- README:212 states `reload` is "automatically executed every 5 hours". No such timer exists: `grep` shows `ReloadConfig` is called only from the `add` and `reload` command branches (`core/server/monitor.go:356`, `:379`).
- README:89 documents `proxy.maxLogLength` as a config field, but `domains.Proxy` has no such JSON tag (`core/domains/domain.go:94-103`) and `examples/config.json:4` sets it anyway — it is silently ignored. `proxy.MaxLogLength` is derived solely from terminal height minus 15 (`core/server/monitor.go:73-78`), so the HUD's log depth changes when the SSH window resizes. README:180 also documents a `connections` HUD field that `printStats` never prints.
- The 1 s HUD loop holds `firewall.Mutex.Lock()` across `checkAttack` for every domain (`core/server/monitor.go:88-92`), and the same loop calls `term.GetSize`, `cpu.Percent` and dozens of `fmt.Println` writes to stdout under `PrintMutex`. A slow or blocked terminal (SSH backpressure, `screen` detached with a full buffer) therefore stalls the stats loop, and `evaluateRatelimit` cannot pre-create the next window buckets — the comment at `core/server/middleware.go:88-95` documents the resulting nil-map write that deadlocks the whole proxy.
- `evaluateRatelimit` (`core/server/monitor.go:576`) is the only long-running goroutine with no `defer pnc.PanicHndl()`, and it also owns the `proxy.Initialised` flag that `main` blocks on (`main.go:43-45`, set at `core/server/monitor.go:631`). It takes `firewall.Mutex.Lock()` for the full rebuild of three maps every 5 seconds.
- `generateOTPSecrets` sleeps one hour (`core/server/monitor.go:657`) but keys the OTP off `currTime.Format("2006-01-02")` (`:651`) — date only. The rotation is therefore daily-at-midnight with an hour of granularity, not hourly, despite the comment at `:646` claiming it "has now been changed to an hour".
- `clearProxyCache` (`core/server/monitor.go:533`) only evicts `CacheIps`/`CacheImgs` when `cpu < 15 && mem > 25` or `mem > 95` (`:552`, `:564`), parsing `proxy.CpuUsage`/`proxy.RamUsage` back out of preformatted strings. Under sustained load (CPU >= 15) the caches are never swept, and `imgCachelen` is counted at `:559-563` but never used.
- `PanicHndl` re-panics after logging (`core/pnc/panicHandler.go:30`), so a recovered panic in `Monitor`, `commands`, `Serve` or `SendWebhook` still terminates the process. It also allocates a 4 096 000-byte stack buffer per invocation and only captures the current goroutine (`runtime.Stack(..., false)`, `:26`).
- The crash-log timestamp format is `"15:05:04"` (`core/pnc/panicHandler.go:28` and `:35`) — the minute field is written with the seconds pattern and vice versa, so every crash.log line has a wrong time. `crash.log` is also opened twice: once in `main` for a deferred close (`main.go:21`) and again in `pnc.InitHndl` (`core/pnc/panicHandler.go:16`). `log.SetOutput(io.Discard)` (`main.go:32`) means nothing else is ever logged anywhere.
- The request middleware has no panic recovery at all — by design, per the comment at `core/server/middleware.go:31` ("we wont do this during prod, to avoid overhead"). Any panic while serving a request takes the whole process down.
- `SendWebhook` uses a bare `&http.Client{}` with no timeout for the Discord POST (`core/utils/discord.go:248`) and discards both the response and the error (`:249`). A hung Discord endpoint leaks a goroutine per alert; alerts fire per domain from `checkAttack` at attack start and at cooldown expiry.
